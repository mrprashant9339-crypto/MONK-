## Implemented during this audit
1. Added migration `20261112123000_task_edit_archive_rpcs.sql`.
2. Added `public.update_task_details(uuid,text,text,date)`:
   - Requires authenticated user and active organization.
   - Locks and checks the task inside the active organization.
   - Requires owner/admin/manager, or assigned contributor/vendor.
   - Validates title length and priority.
   - Updates title, priority and due date and writes an audit event.
3. Added `public.archive_task(uuid)`:
   - Requires authenticated user and active organization.
   - Locks and checks the task inside the active organization.
   - Applies the same role/assignee authorization model.
   - Soft-deletes the task and writes an audit event.
4. Both RPCs revoke execution from PUBLIC and anon and grant execution to authenticated.
5. Frontend task rows now expose edit and archive actions.
6. Focus timer now runs a 25-minute browser timer with pause and reset.
7. README updated to describe current capabilities and limitations.

## Outstanding findings
Supabase security advisor continues to report:
- `citext` extension installed in public schema.
- SECURITY DEFINER functions callable by authenticated users. These include application RPCs and authorization helpers used by RLS; review each function body and grant separately. Do not revoke all helpers blindly.
- Leaked password protection is disabled. Enable it in Supabase Auth password/security settings after reviewing the project auth configuration.
Supabase performance advisor reports unindexed foreign keys, RLS auth initplan warnings, multiple permissive policies and unused indexes. Review against actual query patterns before changing indexes/policies.
